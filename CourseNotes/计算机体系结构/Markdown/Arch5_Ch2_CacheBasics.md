## 一、为什么需要存储层次？

### 1.1 处理器与内存之间的性能鸿沟

计算机历史上最显著的不平衡：

| 技术 | 性能增长速率 |
|------|------------|
| 处理器（CPU） | 约 **60%/年** |
| DRAM 内存 | 约 **7%/年** |

**结果**：CPU-内存性能差距每年扩大约 **50%**。

1980 年时二者速度相近，但到 2000 年，CPU 速度是 DRAM 的 **1000 倍以上**——这就是著名的"内存墙"（Memory Wall）。

1980 年代的微处理器没有片上 Cache；1989 年 Intel 首次在微处理器上集成 Cache；1995 年时两级 Cache 已经成为片上标配。

### 1.2 不同计算场景的关注点

| 计算场景 | 主要关注 |
|----------|----------|
| **桌面/PC** | **平均访问延迟**（单用户单应用） |
| **服务器** | **内存带宽**（数百用户并发，多任务） |
| **嵌入式/实时** | **最坏情况性能**（非最佳情况）、**功耗** |

### 1.3 存储层次的目标

> 目标：以**最便宜内存的成本**，提供**最快内存的速度**。

实现方法：利用**局部性原理（Principle of Locality）**

```
寄存器（RF）
    ↕ 极快
一级Cache（L1）
    ↕ 快
二级Cache（L2）
    ↕ 较快
三级Cache（L3）
    ↕ 慢
主存（DRAM）
    ↕ 很慢
磁盘（SSD/HDD）
    ↕ 极慢
网络存储
```

**越靠近 CPU → 越快、越小、越贵**

### 1.4 局部性原理的应用

**时间局部性（Temporal Locality）**：
- 最近访问的数据很快还会被访问
- 解决方案：**把最近访问的数据保留在靠近 CPU 的高速存储中**

**空间局部性（Spatial Locality）**：
- 刚访问的地址附近的数据很快也会被访问
- 解决方案：**把刚访问地址附近的一块连续数据（块 Block）一起搬到高速存储**

### 1.5 Cache 的通用定义

> Cache 是**用来改善慢速内存平均访问时间的小容量高速存储器**。

计算机中"Cache"无处不在：

| Cache 的实例 | 作用 |
|-------------|------|
| 寄存器（Registers） | 变量的 Cache（软件管理） |
| L1 Cache | L2 Cache 的 Cache |
| L2 Cache | 主存的 Cache |
| 主存（DRAM） | 磁盘的 Cache（虚拟内存） |
| TLB | 页表的 Cache |
| 分支预测缓冲 | 预测信息的 Cache |

## 二、Cache 设计的四个核心问题

### 2.1 四问框架

所有 Cache（以及存储层次）的设计，都可以用以下四个问题来描述和分类：

| 问题 | 关键词 | 选项 |
|------|--------|------|
| Q1：数据块放在哪？ | **块放置（Block Placement）** | 直接映射 / 组相联 / 全相联 |
| Q2：如何找到数据块？ | **块识别（Block Identification）** | 标签（Tag）比较 |
| Q3：替换哪个块？ | **块替换（Block Replacement）** | 随机 / LRU / FIFO |
| Q4：写操作怎么处理？ | **写策略（Write Strategy）** | 写通（Write-Through）/ 写回（Write-Back）|

---

### Q1：块放置策略

#### 直接映射（Direct Mapped）

- 每个内存块**只能放到 Cache 中唯一确定的位置**
- 映射规则：`Cache 块编号 = 内存块地址 MOD Cache 总块数`
- 优点：硬件简单，查找速度快
- 缺点：冲突率高（多个热点内存块争用同一 Cache 槽）

#### 全相联（Fully Associative）

- 内存块可以放到 Cache 中**任意位置**
- 优点：冲突率最低，Cache 利用率高
- 缺点：查找时需要**同时比较所有 Cache 块的 Tag**，硬件复杂，功耗高

#### 组相联（Set Associative）

- Cache 被分成若干**组（Set）**，每组有 $n$ 个槽（Way）
- 映射规则：`组编号 = 内存块地址 MOD 组数`，组内任意放
- 称为 **n 路组相联（n-Way Set Associative）**
- 是直接映射和全相联的折中，实际系统中最常用

**关系**：
- 直接映射 = 1路组相联
- 全相联 = m路组相联（m = Cache 总块数）

**示例**（8块内存 → 4块 Cache）：

| 策略 | 灵活性 | 硬件复杂度 |
|------|--------|------------|
| 直接映射 | 最低（内存块0必须用Cache块0） | 最简单 |
| 2路组相联 | 中等 | 中等 |
| 全相联 | 最高（可放任意位置） | 最复杂 |

---

### Q2：块识别方式

物理地址被分成三个字段：

```
| ← Tag位 → | ← Index位 → | ← Byte Offset位 → |
```

| 字段 | 位数 | 作用 |
|------|------|------|
| **Byte Offset** | $\log_2(\text{块大小（字节）})$ | 定位块内某字节 |
| **Index** | $\log_2(\text{组数})$ | 选择要查的组（或直接映射时选块） |
| **Tag** | 地址总位数 - Index位 - Offset位 | 与 Cache 中存储的 Tag 比较，判断是否命中 |

**命中判断过程**：
1. 用 Index 字段找到对应的组（或 Cache 槽）
2. 将地址的 Tag 字段与组中各路的 Tag 比较
3. 若相等且 **Valid 位（有效位）** 为 1 → **Cache 命中（Hit）**
4. 否则 → **Cache 缺失（Miss）**，需从下级存储取数据

**Valid 位**：冷启动或上下文切换后，Cache 中的数据未必有效，Valid 位用于标记某个 Cache 块是否包含有效数据。

---

### Q3：块替换策略

当 Cache 缺失需要装入新数据块，而对应位置已满时，需要**替换（Evict）** 一个旧块：

| 策略 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **随机（Random）** | 随机选择一个替换 | 实现极简（只需随机数生成器）| 可能驱逐即将再用的块 |
| **LRU（Least Recently Used）** | 替换最久未使用的块 | 命中率通常最高 | 需要额外硬件记录访问顺序（位数随路数增加）|
| **FIFO** | 替换最先进入 Cache 的块 | 比 LRU 简单 | 性能略差于 LRU |

**实践**：
- 2路、4路组相联：通常使用 **LRU 或伪LRU**
- 高路数（8路及以上）：LRU 硬件开销大，常退化为**随机替换**（性能差距不大）

---

### Q4：写操作策略

#### 写通（Write-Through）

- **每次写 Cache 时，同时写到下级存储（主存）**
- 优点：
  - Cache 和内存**始终一致**
  - 读缺失时**不需要将旧数据写回**（因为内存已是最新值）
  - 实现简单
- 缺点：
  - **写操作产生停顿（Write Stall）**：CPU 必须等待写操作完成

**写缓冲（Write Buffer）**：解决写停顿的缓解措施
- 写操作先写入小容量的写缓冲（几个~几十个项）
- CPU 继续执行，写缓冲在后台慢慢将数据写入内存
- 若写缓冲满了，CPU 才需要停顿等待

#### 写回（Write-Back）

- **写操作只更新 Cache，不立即写内存**
- Cache 块的 **Dirty 位（脏位）** 标记该块已被修改
- 只有当该 Cache 块被替换时，才将脏块写回内存
- 优点：
  - 写速度快（写到 Cache 即完成）
  - **内存带宽需求低**（对同一块的多次写只产生一次内存写）
- 缺点：
  - 数据在 Cache 和内存之间可能不一致
  - 需要 Dirty 位，处理逻辑复杂

**对比总结**：

| 特性 | 写通 | 写回 |
|------|------|------|
| Cache 与内存一致性 | 始终一致 | 可能不一致（Dirty块）|
| 读缺失处理 | 简单（不需写回旧块）| 需要检查 Dirty 位，可能先写回 |
| 内存带宽 | 较高（每次写都消耗）| 较低（写合并）|
| 控制位 | 只需 Valid 位 | 需要 Valid + Dirty 位 |
| 适用场景 | 简单系统、L1 Cache | 复杂系统、L2/L3 Cache |

#### 写缺失策略

当写操作发生 Cache 缺失时（要写的地址不在 Cache 中）：

| 策略 | 行为 | 通常与谁配合 |
|------|------|------------|
| **写分配（Write Allocate）** | 先把该块从内存调入 Cache，再写 | **写回（Write-Back）** |
| **写不分配（Write Around / No-Write Allocate）** | 直接写内存，不调入 Cache | **写通（Write-Through）** |

**例题**：全相联写回 Cache，初始为空，五次操作：

| 操作 | write-allocate | no-write-allocate |
|------|----------------|-------------------|
| 写[100] | **缺失**（装入再写）| **缺失**（直接写内存）|
| 写[100] | **命中**（Cache已有）| **缺失**（仍不在Cache）|
| 读[200] | **缺失**（装入）| **缺失**（装入）|
| 写[200] | **命中** | **命中** |
| 写[100] | **命中** | **缺失** |

- write-allocate：缺失2次，命中3次
- no-write-allocate：缺失4次，命中1次

## 三、分离 Cache 与统一 Cache

| 类型 | 说明 | 优缺点 |
|------|------|--------|
| **统一 Cache（Unified Cache）** | 指令和数据共用一个 Cache | 硬件少，但 IF 阶段和 MEM 阶段可能冲突（结构冒险）|
| **分离 Cache（Split I&D Cache）** | 指令 Cache 和数据 Cache 分开 | 消除流水线结构冒险，指令 Cache 只读（更简单），但总容量分散 |

现代处理器 L1 级通常使用**分离 Cache**，L2、L3 级通常使用统一 Cache。

**真实案例：Alpha 21264 数据 Cache（2路组相联）**

四步访问过程：
1. 用 Index 字段读出两路（Way 0 和 Way 1）的 Tag
2. 同时并行比较两个 Tag 与地址 Tag 字段
3. 选出匹配的那路，检查 Valid 位
4. 若命中，取出数据；否则从主存获取

Alpha 21264 允许上述四步在 3 个时钟周期内完成，因此 Load 指令的结果需要 2 个周期的停顿。

## 四、Cache 性能分析

### 4.1 关键公式

$$\text{CPU 执行时间} = (\text{CPU 时钟周期数} + \text{内存停顿周期数}) \times \text{时钟周期时间}$$

$$\text{内存停顿周期数} = \text{指令数} \times \text{缺失率} \times \text{缺失惩罚（Miss Penalty）}$$

$$\text{平均内存访问时间（AMAT）} = \text{命中时间} + \text{缺失率} \times \text{缺失惩罚}$$

其中 **AMAT = Average Memory Access Time**，"命中时间"指 Cache 命中时的访问时间（通常 1~3 个时钟周期）。

### 4.2 例题 1：Cache 对 CPI 的影响

**条件**：
- 时钟频率 200 MHz（每周期 5ns），理想 CPI = 1.1
- 指令分布：50% 算术逻辑，30% 访存，20% 控制
- 数据缺失率 10%，缺失惩罚 50 周期
- 指令缺失率 1%，缺失惩罚 50 周期

**计算**：
$$CPI = 1.1 + (0.30 \times 0.10 \times 50) + (1 \times 0.01 \times 50)$$
$$= 1.1 + 1.5 + 0.5 = 3.1$$

Cache 缺失使 CPI 从 1.1 增加到 3.1，**增加了约 2.8 倍**！

$$AMAT = \frac{1}{1.3} \times (1 + 0.01 \times 50) + \frac{0.3}{1.3} \times (1 + 0.1 \times 50) = 2.54 \text{ 周期}$$

### 4.3 例题 2：有 Cache vs 无 Cache

**条件**：理想 CPI=1，50% 指令为访存，缺失惩罚 25 周期，缺失率 2%

**有 Cache 时的内存停顿周期**：
$$\text{内存停顿} = IC \times (1 \times 0.01 \times 25 + 0.5 \times 0.02 \times 25) = IC \times 0.75$$
$$CPU \text{时间}_{Cache} = IC \times (1.0 + 0.75) \times T = 1.75 \times IC \times T$$

**全命中（完美Cache）**：$CPU\text{时间} = IC \times 1.0 \times T$

**完全没有 Cache（每次访存都要去内存）**：
$$CPI = 1.0 + 1.5 \times 100 = 151$$（约为有Cache的 **40 倍** 慢！）

→ Cache 的重要性不言而喻。

### 4.4 例题 3：分离 Cache vs 统一 Cache

**条件**：
- 统一 Cache：32KB；分离 Cache：各 16KB
- 指令访问占 74%，数据访问占 26%
- 命中时间 1 周期，缺失惩罚 100 周期
- 统一 Cache 指令读需额外 1 周期

从图表（教材图2.32）得：
- 32KB 统一 Cache 缺失率 = 3.18%
- 16KB 指令 Cache 缺失率 = 0.4%，16KB 数据 Cache 缺失率 = 11.4%

**分离 Cache 有效缺失率**：$74\% \times 0.004 + 26\% \times 0.114 = 3.24\%$（略高于统一 Cache 的 3.18%）

**但 AMAT 分离 Cache 更优**（因消除了结构冒险）：
$$AMAT_{split} = 74\% \times (1 + 0.004 \times 100) + 26\% \times (1 + 0.114 \times 100) = 4.24 \text{ 周期}$$
$$AMAT_{unified} = 74\% \times (1 + 0.0318 \times 100) + 26\% \times (1 + 1 + 0.0318 \times 100) = 4.44 \text{ 周期}$$

→ **分离 Cache 的 AMAT 更小**，尽管其有效缺失率略高，原因是消除了流水线结构冒险（分离后 IF 和 MEM 不再竞争同一端口）。

### 4.5 例题 5：组相联 vs 直接映射的性能对比

**条件**：
- 直接映射：缺失率 1.4%，时钟周期 1.0ns
- 2路组相联：缺失率 1.0%，但多路选择器使时钟周期延长 1.25 倍 = 1.25ns
- 缺失惩罚 75ns

$$AMAT_{1-way} = 1.0 + 0.014 \times 75 = 2.05 \text{ ns}$$
$$AMAT_{2-way} = 1.25 + 0.010 \times 75 = 2.00 \text{ ns}$$

→ **2路组相联的 AMAT 更小**（尽管命中时间更长，但缺失率下降弥补了这一点）。

## 五、Cache 优化的方向总览

本章只是基础，后续将针对以下四个方向深入展开 17 种优化技术：

| 优化方向 | 技术数量 | 代表技术 |
|----------|----------|----------|
| **减少缺失惩罚** | 5种 | 多级 Cache、关键字优先、写缓冲合并 |
| **降低缺失率** | 5种 | 更大块、更大容量、更高相联度、编译器优化 |
| **利用并行降低缺失惩罚/率** | 3种 | 非阻塞 Cache、硬件预取、编译器预取 |
| **减少命中时间** | 4种 | 小而简单的 Cache、流水化 Cache 访问 |

## 六、总结

Cache 设计围绕**三个核心指标**展开：

$$\text{AMAT} = \text{命中时间} + \text{缺失率} \times \text{缺失惩罚}$$

降低 AMAT 的三条路径：
1. **降低命中时间**：小而简单的 Cache，流水化访问
2. **降低缺失率**：更大/更灵活/更优化的 Cache
3. **降低缺失惩罚**：多级 Cache，并行处理缺失

**四问框架是理解所有 Cache 设计的基础**：
- Q1 块放置 → 相联度的选择
- Q2 块识别 → Tag/Index/Offset 地址划分
- Q3 块替换 → LRU/随机/FIFO
- Q4 写策略 → 写通/写回 + 写分配/写不分配

> **下一章**将深入讨论如何**减少 Cache 缺失（Miss Rate）**，包括三种缺失类型（3C）和各种针对性的优化技术。
