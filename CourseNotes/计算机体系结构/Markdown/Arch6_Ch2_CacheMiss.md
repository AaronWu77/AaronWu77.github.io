# 第二章：存储层次设计（中）—— Cache 缺失优化

## 一、概述

在上一章（§5.1~§5.3）我们学习了 Cache 的基本结构和四问框架，并建立了 AMAT 性能模型：

$$\text{AMAT} = \text{命中时间} + \text{缺失率} \times \text{缺失惩罚}$$

本章系统介绍 **17 种 Cache 优化技术**，分为四大方向：
1. **减少缺失惩罚（Miss Penalty）** — 5 种
2. **降低缺失率（Miss Rate）** — 5 种
3. **利用并行同时减少缺失惩罚和缺失率** — 3 种
4. **减少命中时间（Hit Time）** — 4 种

---

## 二、方向一：减少缺失惩罚（§5.4）

### 技术1：多级 Cache（Multilevel Caches）

#### 动机

单级 Cache 面临矛盾：
- **L1 Cache 要快** → 小而直接映射
- **Cache 要能挡住大量访存请求** → 大而高相联

解决方案：**在 L1 Cache 与主存之间增加 L2 Cache**（甚至 L3）。

- **L1 Cache**：小而快，主要降低命中时间
- **L2 Cache**：大而慢，主要承接 L1 的缺失，减少去主存的频率

#### AMAT 公式（两级 Cache）

$$\text{AMAT} = \text{命中时间}_{L1} + \text{缺失率}_{L1} \times \text{缺失惩罚}_{L1}$$

$$\text{缺失惩罚}_{L1} = \text{命中时间}_{L2} + \text{缺失率}_{L2}^{local} \times \text{缺失惩罚}_{L2}$$

**展开**：

$$\text{AMAT} = \text{命中时间}_{L1} + \text{缺失率}_{L1} \times (\text{命中时间}_{L2} + \text{缺失率}_{L2}^{local} \times \text{缺失惩罚}_{L2})$$

#### 局部缺失率 vs 全局缺失率

| 指标 | 定义 | 意义 |
|------|------|------|
| **局部缺失率（Local Miss Rate）** | 该 Cache 的缺失次数 / 该 Cache 的访问次数 | L2 的局部缺失率较高（因为 L1 已过滤掉容易命中的请求）|
| **全局缺失率（Global Miss Rate）** | 该 Cache 的缺失次数 / CPU 总内存访问次数 | **更有意义**，表示多少比例的访问需要穿透到下一级 |

**注意**：L2 的局部缺失率看起来较高，但全局缺失率才是关键指标。

**每条指令的内存停顿**（两级 Cache）：

$$\text{内存停顿/指令} = \frac{\text{L1缺失数}}{1000\text{条指令}} \times \text{命中时间}_{L2} + \frac{\text{L2缺失数}}{1000\text{条指令}} \times \text{缺失惩罚}_{L2}$$

**例题7**（两级 Cache）：
- L1：每1000次内存访问 40次缺失，命中时间 1 周期
- 每条指令1.5次内存访问
- L2：每1000次内存访问 20次缺失（局部），命中时间 10 周期，缺失惩罚 100 周期

全局缺失数：
- L1全局：$1.5 \times 4\% \times 1000 = 60$ 次/1000指令
- L2全局：$1.5 \times 2\% \times 1000 = 30$ 次/1000指令

每条指令停顿 = $(60/1000) \times 10 + (30/1000) \times 100 = 0.6 + 3.0 = 3.6$ 周期

**例题8**（L2 相联度对 Miss Penalty 的影响）：
- 直接映射 L2：命中时间 10 周期，局部缺失率 25%
- 2路组相联 L2：命中时间 10.1 周期，局部缺失率 20%

$$MP_{1-way} = 10 + 25\% \times 100 = 35.0 \text{ 周期}$$
$$MP_{2-way} = 10.1 + 20\% \times 100 = 30.1 \text{ 周期}$$

→ **2路组相联 L2 的缺失惩罚更小**（从 35 降到 30.1），即使命中时间略有增加，降低缺失率的收益更大。

### 技术2：关键字优先（Critical Word First）与提前重启（Early Restart）

**背景**：Cache 缺失时需要从内存取一整个块（Block），通常 CPU 需等全部数据到达才恢复执行。

**优化方案**：
- **关键字优先（Critical Word First）**：先从内存取 CPU 当前需要的那个字（关键字），立即发送给 CPU，让 CPU 继续执行；其余字在后台继续填充。也称为"环形取（Wrapped Fetch）"或"请求字优先（Requested Word First）"。
- **提前重启（Early Restart）**：等待请求的字到达后立即恢复 CPU，不等整块填完。

**适用场景**：大块 Cache，空间局部性较强时更有效。

**例题9**：
- Cache 块 = 64字节
- AMD Athlon：L2 获取关键 8 字节需 11 周期，之后每 8 字节需 2 周期
- 使用关键字优先：平均缺失惩罚 = **11 周期**
- 不使用：需等整块（11 + 7×2 = 25 周期），再加读取时间，共 29 周期
- 节省约 18 周期

---

### 技术3：优先处理读缺失（Priority to Read Misses over Writes）

**问题场景**（写通 Cache + 写缓冲）：

```
SW R3, 512(R0)   ; 写入 M[512]，进写缓冲
LW R1, 1024(R0)  ; 读 M[1024]（与M[512]映射到同一Cache块）→ 缺失
LW R2, 512(R0)   ; 读 M[512]，此时写缓冲可能还没写入内存！
```

如果读缺失直接去内存取，但写缓冲还没完成写入，就会读到**旧数据**（RAW 数据冒险）。

**解决方案**：
1. 发生读缺失时，先**检查写缓冲**：若写缓冲中没有与读地址冲突的项 → 允许读继续
2. 若有冲突 → 要么等写缓冲排空，要么直接从写缓冲转发数据

对于**写回 Cache**：读缺失时如果要替换的块是脏块，通常做法是先把脏块复制到写缓冲，然后立即开始读（而不是等写完再读），CPU 停顿时间更短。

---

### 技术4：合并写缓冲（Merging Write Buffer）

**想法**：写通 Cache 的写缓冲中，如果新写入的地址与缓冲中某个有效项的地址**相邻或相同**，可以将它们**合并为一个宽写操作**，提高内存写带宽利用率。

**效果**：
- 将多个单字写合并为多字写，降低内存总线事务数
- 减少写缓冲满溢导致 CPU 停顿的概率

---

### 技术5：Victim Cache（受害者缓存）

**问题**：直接映射 Cache 中，若多个热点地址映射到同一 Cache 行，会频繁冲突（乒乓效应）。

**解决方案**：在 L1 Cache 与 L2 Cache 之间插入一个**小型全相联缓冲（通常 4~16 项）**，专门存放刚被 L1 替换出去的块。

**工作流程**：
1. L1 缺失 → 先检查 Victim Cache
2. 若 Victim Cache 命中 → **"伪命中（pseudo-hit）"**：将数据从 Victim Cache 取出，与 L1 当前块交换
3. 若仍缺失 → 去 L2/主存取数据

**效果**：Jouppi [1990] 研究显示，4项 Victim Cache 可以消除 4KB 直接映射数据 Cache 中 20%~95% 的冲突缺失。

**应用**：Alpha、HP 服务器处理器都采用了 Victim Cache。

## 三、方向二：降低缺失率（§5.5）

### 3C 缺失分类法

理解缺失原因是降低缺失率的前提：

| 类型 | 英文 | 定义 | 对应极限缓存 |
|------|------|------|------------|
| **强制缺失** | Compulsory Miss | 第一次访问某块时，该块必然不在 Cache 中 | 即使无限大 Cache 也会发生 |
| **容量缺失** | Capacity Miss | Cache 容量不足以存放程序工作集 | 无限大全相联 Cache 中消失 |
| **冲突缺失** | Conflict Miss | 多个内存块争用同一 Cache 位置 | 无限相联度时消失 |
| **（一致性缺失）** | Coherence Miss | 多处理器场景，Cache 间一致性协议导致失效 | — |

**3C 分析图（参考 SPEC92）**：
- 随 Cache 容量增大，容量缺失减少
- 随相联度增大，冲突缺失减少
- 强制缺失与 Cache 大小无关（但与块大小有关）

---

### 技术6：增大块大小（Larger Block Size）

**原理**：利用空间局部性，每次从内存取更多连续数据，减少强制缺失。

**代价**：
- 同样容量的 Cache，块越大 → Cache 总块数越少 → 冲突缺失**增加**
- 块越大 → 缺失时需要传输更多数据 → 缺失惩罚**增加**

**性能曲线为"U形"**：块大小存在最优值（通常 32~128 字节）。

**例题11**（最优块大小）：
- 内存系统固定开销 80 周期，之后每 16 字节需 2 周期
- 命中时间 1 周期

| Cache大小 | 块大小 | 缺失率 | AMAT |
|----------|--------|--------|------|
| 1KB | 16B | 15.05% | 1 + 15.05% × 82 = 13.3 |
| 256KB | 256B | 0.49% | 1 + 0.49% × 112 = 1.55 |

→ 块大小的选择需结合 **Cache 容量、内存带宽和延迟** 综合考虑。

---

### 技术7：增大 Cache 容量（Larger Caches）

- **经验规律（Rule of Thumb）**：Cache 容量每增大 2 倍，缺失率下降约 **25%**
- 缺点：增大命中时间（检索时间增加）、成本提高

**工作集（Working Set）**：程序在一段时间内频繁访问的内存集合。当 Cache 足够大，能容纳整个工作集时，缺失率会急剧下降（容量缺失消失）。

---

### 技术8：提高相联度（Higher Associativity）

- **经验规律（2:1 法则）**：N 大小的直接映射 Cache 的缺失率 ≈ N/2 大小的 2路组相联 Cache 的缺失率
- 8路组相联已接近全相联的效果
- 缺点：相联度越高，命中时间越长（选择器延迟增加）

**例题12**（相联度 vs 时钟周期时间的折中）：
- 假设：2路相联使时钟延长 1.36 倍，4路 1.44 倍，8路 1.52 倍
- 缺失惩罚 25 周期

各配置 AMAT（以4KB Cache 为例，直接映射缺失率约 9.8%）：
$$AMAT_{1-way} = 1.00 + 0.098 \times 25 = 3.44 \text{ ns}$$
$$AMAT_{2-way} = 1.36 + miss_{2-way} \times 25$$

→ **结论**：相联度提高不总是改善性能，必须考虑对时钟周期的影响。

---

### 技术9：路预测与伪相联（Way Prediction & Pseudo-Associative）

**目标**：兼顾直接映射的快命中和组相联的低冲突。

#### 路预测（Way Prediction）

- 在 Cache 块中增加**预测位（Predictive Bit）**，预测下次访问会命中哪路
- 若预测正确 → 命中时间 = 直接映射（1 周期）
- 若预测错误 → 需检查另一路，命中时间 = 3 周期
- **Alpha 21264** 在 2路指令 Cache 上使用，SPEC95 仿真显示预测精度 > 85%

#### 伪相联（Pseudo-Associative / Column Associative Cache）

- 直接映射 Cache 缺失时，检查同列的**另一路**（同地址的另一 Cache 半部）
- 若找到 → **伪命中（pseudo-hit）**（比正常命中慢，比真缺失快）
- 适合 L2 Cache（不直接连接流水线，周期数不严格要求整数）
- 应用：MIPS R1000 L2 Cache、UltraSPARC

---

### 技术10：编译器优化（Compiler Optimizations）

无需硬件改动，通过**代码变换**改善缓存局部性：

#### ① 循环交换（Loop Interchange）

```c
/* 优化前：跨列访问，步长100，每次100字 */
for (k = 0; k < 100; k++)
  for (j = 0; j < 100; j++)
    for (i = 0; i < 5000; i++)
      x[i][j] = 2 * x[i][j];   // 访问 x[0][j], x[1][j],...步长=100

/* 优化后：按行访问，步长1，空间局部性好 */
for (k = 0; k < 100; k++)
  for (i = 0; i < 5000; i++)
    for (j = 0; j < 100; j++)
      x[i][j] = 2 * x[i][j];   // 访问 x[i][0], x[i][1],...步长=1
```

将空间局部性差的**跨步访问**改为连续访问。

#### ② 分块（Blocking）

**问题**：矩阵乘法 `x[i][j] += y[i][k] * z[k][j]` 中，z 矩阵是跨列访问，N×N 矩阵总访问次数 $2N^3 + N^2$。

**解决**：将矩阵划分为 B×B 的**子块**，每次对子块进行运算：

```c
for (jj = 0; jj < N; jj += B)
  for (kk = 0; kk < N; kk += B)
    for (i = 0; i < N; i++)
      for (j = jj; j < min(jj+B, N); j++) {
        r = 0;
        for (k = kk; k < min(kk+B, N); k++)
          r += y[i][k] * z[k][j];
        x[i][j] += r;
      }
```

- 容量缺失从 $2N^3 + N^2$ 降到 $\dfrac{2N^3}{B} + N^2$（减少了 B 倍！）
- **B 称为分块因子（Blocking Factor）**，选择 B 使子块能完全放入 Cache

#### ③ 循环合并（Loop Fusion）

```c
/* 优化前：两个独立循环，访问 a 和 c 各两次 */
for (i=0; i<N; i++)
  for (j=0; j<N; j++)
    a[i][j] = 1/b[i][j] * c[i][j];
for (i=0; i<N; i++)
  for (j=0; j<N; j++)
    d[i][j] = a[i][j] + c[i][j];

/* 优化后：合并为一个循环，a 和 c 各只访问一次 */
for (i=0; i<N; i++)
  for (j=0; j<N; j++) {
    a[i][j] = 1/b[i][j] * c[i][j];
    d[i][j] = a[i][j] + c[i][j];
  }
```

#### ④ 数组合并（Merging Arrays）

```c
/* 优化前：两个独立数组，可能在 Cache 中发生冲突 */
int val[SIZE];
int key[SIZE];

/* 优化后：合并为结构体数组，val 和 key 紧邻存储 */
struct merge { int val; int key; };
struct merge merged_array[SIZE];
```

减少 val 和 key 之间的冲突缺失，同时改善空间局部性。

## 四、方向三：通过并行减少缺失惩罚/缺失率（§5.6）

### 技术11：非阻塞 Cache（Nonblocking Cache / Lockup-Free Cache）

**传统（阻塞）Cache**：Cache 缺失时，CPU 停顿，等数据返回后继续。

**非阻塞 Cache**：允许 Cache 在处理一次缺失期间，**继续服务后续的命中请求**（乃至其他缺失）。

- **缺失时命中（Hit Under Miss）**：一次未完成的缺失期间，Cache 可以继续服务命中请求
- **多次缺失（Miss Under Miss）**：允许同时有多个未完成的缺失挂起

**需要配合乱序执行（OOO）处理器** 才能充分发挥效果。

**效果**（例题13）：对8KB 直接映射 Cache，缺失惩罚 16 周期：
- 浮点程序：hit under 1 miss 将平均停顿时间降至阻塞缓存的 **76%**
- 整数程序：降至 **81%**（相当于 2路组相联的效果）

→ 对于浮点程序，直接映射 Cache + hit-under-miss 的性能优于 2路组相联阻塞 Cache！

---

### 技术12：硬件预取（Hardware Prefetching）

**原理**：在 CPU 真正需要某块数据之前，提前将其从内存取到 Cache（或预取缓冲区）。

**关键设计**：
- 预取到**流缓冲区（Stream Buffer）**，而不直接放入 Cache（避免污染已有数据）
- 实际需要时再从流缓冲区转移到 Cache

**例子**：Alpha 21064 每次指令缺失时额外预取**下一个块**，存放到 stream buffer，后续访问直接命中 stream buffer。

**前提**：需要额外的内存带宽。若内存已满负荷，预取可能反而降低性能。

---

### 技术13：编译器控制预取（Compiler-Controlled Prefetch）

**原理**：编译器在代码中插入**预取指令（prefetch instruction）**，提前 N 次迭代发出预取请求，使数据在需要前到达。

```c
/* 在 j 迭代中预取第 j+7 次迭代需要的数据 */
for (j = 0; j < 100; j++) {
    prefetch(b[j+7][0]);   /* 预取 7 次后需要的 b */
    prefetch(a[0][j+7]);   /* 预取 7 次后需要的 a */
    a[0][j] = b[j][0] * b[j+1][0];
}
```

**例题13（编译器预取）**：
- 原始代码：251 次缺失，总时间 $3 \times 100 \times 7 + 251 \times 100 = 27,200$ 周期
- 预取后：19 次缺失，共 400 条预取指令，总时间 4,400 周期
- **性能提升约 6.2 倍**！

**两种预取方式**：
| 类型 | 预取到 | 能否出错 |
|------|-------|---------|
| 绑定预取（Binding Prefetch）| 寄存器 | 必须地址正确 |
| 非绑定预取（Non-Binding Prefetch）| Cache | 地址可以有误，不触发异常 |

## 五、方向四：减少命中时间（§5.7）

### 技术14：小而简单的 Cache（Small and Simple Caches）

- 硬件越少 → 关键路径越短 → 访问速度越快
- 直接映射比组相联快（读写都快，因为不需要选择器）
- L1 Cache 通常设计为**小容量+直接映射/2路相联**，追求最低命中时间

---

### 技术15：避免地址翻译（Avoiding Address Translation during Indexing）

**背景**：CPU 使用虚拟地址（VA），内存访问需要翻译为物理地址（PA）；Cache 使用物理地址比较 Tag。

**翻译流程**：VA → TLB 查找 → PA → Cache 查找

**优化思路**：物理地址中的**页内偏移（Page Offset）部分不会被翻译改变**，可以用页内偏移中的某些位直接作为 Cache 的 Index，从而让 **Cache 索引与地址翻译并行进行**。

```
VA:  [ VPN | Page Offset ]
PA:  [ PPN | Page Offset ]
                   ↑
            这部分不变！可以直接用于Cache Index
```

**约束**：若 Cache Index 完全在 Page Offset 范围内，则：
$$\text{Cache 容量} \leq \text{页大小} \times \text{相联度}$$

若需要更大的 Cache，可以提高相联度或使用**页着色（Page Coloring）**。

#### TLB（Translation Lookaside Buffer，旁路转译缓冲）

TLB 是页表的 Cache，存储最近使用的虚拟→物理地址映射：
- 容量小（通常 128~256 项），但访问速度快（与 L1 Cache 相当）
- 组织方式：全相联（小机器）或 n 路组相联（大机器）

**虚拟 Cache（Virtual Cache）的问题**：
- **进程切换**：切换进程时必须清空 Cache（不同进程的相同虚拟地址映射不同物理地址）
  - 解决：加进程 ID 标签（ASID）
- **别名问题（Aliasing/Synonym Problem）**：两个不同虚拟地址映射到同一物理地址，可能造成 Cache 中存在两个副本不一致
  - 解决：硬件保证 Cache Set 大小 ≤ 页大小（Index 位完全在页内偏移中）

---

### 技术16：流水化 Cache 访问（Pipelined Cache Access）

- 将 Cache 的写操作（tag检查 + 数据写入）流水化：第一个写的第二阶段（数据写入）与第二个写的第一阶段（tag检查）重叠执行
- 提高写操作吞吐量（但写延迟不变）

---

### 技术17：追踪缓存（Trace Cache）

- 普通指令 Cache 按**静态地址顺序**存储指令块
- **追踪缓存（Trace Cache）**：按 CPU 实际**动态执行序列**存储指令块，包括跨过跳转的指令序列
- 将**分支预测结果折叠进 Cache**：每次取指时验证分支结果是否与 Cache 中记录的一致
- 优点：提高取指带宽，减少有效指令缺失率

## 七、总结

本章系统介绍了 Cache 优化的四条主线：

```
AMAT = 命中时间 + 缺失率 × 缺失惩罚

     命中时间↓               缺失率↓              缺失惩罚↓
     - 小而简单Cache        - 大容量               - 多级Cache
     - 避免地址翻译         - 大块大小             - 关键字优先
     - 流水化访问           - 高相联度             - 读优先于写
     - 追踪Cache           - 编译器优化           - 合并写缓冲
                           - 路预测/伪相联        - Victim Cache
                    ←通过并行同时减少→
                    - 非阻塞Cache
                    - 硬件预取
                    - 编译器预取
```

**设计权衡**：
- 高相联度改善缺失率，但增加命中时间
- 大块大小改善强制缺失，但可能增加冲突缺失和缺失惩罚
- 非阻塞 Cache 效果显著，但需要乱序执行硬件支持
