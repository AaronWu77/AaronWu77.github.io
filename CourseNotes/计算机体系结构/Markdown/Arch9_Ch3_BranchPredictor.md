## 一、为什么分支预测很重要？

### 1.1 控制冒险的代价

流水线处理控制冒险的传统方法及其代价：

| 方法 | 代价 |
|------|------|
| **冲刷（Flushing）** | 每次分支都停顿 X 周期 |
| **预测不跳转（Predict-Not-Taken）** | 跳转时浪费 X 周期 |
| **预测跳转（Predict-Taken）** | 不跳转时浪费 X 周期；跳转时也需要等目标地址（Y 周期）|
| **延迟分支（Delayed Branch）** | 编译器填充延迟槽 |

**性能公式**：
$$\text{控制冒险停顿} = f(\text{分支频率}, \text{预测精度}, \text{误预测惩罚})$$

**静态预测（总是预测跳转）** 的误预测率：9%~59%，平均约 **34%**——对于高性能处理器来说太高了。

---

## 二、动态分支预测总览

动态分支预测的关键思想：**根据分支的历史行为预测未来行为**。

本章介绍的预测器：
1. **1位分支预测缓冲（1-bit BHT）**
2. **2位分支预测缓冲（2-bit BHT）**
3. **相关分支预测器（Correlating Branch Predictor）**
4. **竞赛预测器（Tournament Predictor）**
5. **分支目标缓冲（Branch Target Buffer, BTB）**
6. **集成取指单元（Integrated Instruction Fetch Unit）**
7. **返回地址预测器（Return Address Predictor）**

---

## 三、1位分支预测缓冲（1-bit BHT）

**结构**：用 PC 低几位作为索引，访问一个包含 1 位值的表（Branch History Table）。

- 该位记录分支**上次是否跳转**：1 = 跳转，0 = 不跳转
- 每次分支执行后更新

**问题：循环中的"两次误预测"**

以 `while (i < 10)` 为例，循环执行序列：`TTTTT...TTTF TTTTT...TTTF ...`

| 执行 | 实际结果 | 预测（1-bit）| 结果 |
|------|----------|------------|------|
| 第1次循环（迭代1~N-1）| T（跳转）| T（上次跳转）| ✓ |
| **最后一次迭代** | **F（不跳转）** | T（上次跳转）| **✗ 误预测** |
| **循环重启第1次** | **T（跳转）** | F（上次不跳转）| **✗ 误预测** |

→ **每次循环开始和结束各误预测 1 次**，共 **2 次误预测**。若循环执行 n 次迭代，精度为 $(n-2)/n$，当 n 较小时精度很差。

---

## 四、2位分支预测缓冲（2-bit BHT）★

**核心思想**：增加"迟滞（Hysteresis）"——只有**连续两次**预测错误才改变预测方向。

**状态机（饱和计数器）**：

```
    跳转          跳转          跳转
┌──────────┐    ┌──────────┐    ┌──────────┐
│强预测跳转│ ←→ │弱预测跳转│ ←→ │弱预测不跳│ ←→ 强预测不跳
│  (11)    │    │  (10)    │    │  (01)    │    │  (00)    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
    不跳          不跳          不跳
```

- 两种"跳转"预测（11 = 强，10 = 弱）
- 两种"不跳转"预测（01 = 弱，00 = 强）
- 状态转换：跳转 → 计数器+1（饱和），不跳转 → 计数器-1（饱和）

**解决循环问题**：循环最后一次不跳从"强预测跳转"变为"弱预测跳转"，而不是直接翻转到"预测不跳转"。下次循环重启时，"弱预测跳转"遇到跳转 → 立即恢复"强预测跳转"。

→ **循环仍然只有 1 次误预测**（循环退出时），循环开始时不再误预测！

**实现**：2位饱和计数器，用 PC 低位索引一个 BHT 表（例如 4096 项）。

**精度（SPEC89）**：预测精度 **82%~99%**，具体取决于程序特性。

**n位预测器**：可以将2位推广到n位（计数器范围 $[0, 2^n-1]$）：
- 计数器 ≥ $2^{n-1}$：预测跳转
- 计数器 < $2^{n-1}$：预测不跳转
- 但实验表明，2位就已足够，增加更多位改善幅度有限。

## 五、相关分支预测器（Correlating Branch Predictor）★

### 5.1 单纯2位BHT的局限

**关键认识**：**一个分支的行为不仅取决于它自己的历史，还取决于其他分支的最近行为！**

**例1**：
```c
if (aa == 2) aa = 0;     // b1: (aa!=2) 时跳过
if (bb == 2) bb = 0;     // b2: (bb!=2) 时跳过
if (aa == bb) { ... }    // b3: (aa!=bb) 时跳过
```

分析：b3 只有在 b1 **和** b2 都"不跳转"（即 aa=0, bb=0）时才会"跳转"。
- b3 的行为完全由 b1 和 b2 决定！
- 仅靠 b3 自己的历史**无法正确预测** b3。

**例2**：
```c
if (d == 0) d = 1;  // b1
if (d == 1) { ... } // b2: 若 b1 不跳转（d原本=0，现在=1）→ b2 必然不跳转
```

- 如果 b1 不跳转（d=0，执行 d=1），则 b2 的条件 d==1 必然成立 → b2 **必然不跳转**
- 1-bit 预测器对 b2 总是误预测（总是在对的时候预测错的方向）

### 5.2 相关预测器的结构（m, n）

**想法**：用**最近 m 次其他分支的跳转/不跳转历史**来选择 n 位预测器。

**(m, n) 预测器**：
- **m 位全局历史寄存器（Global History Register, GHR）**：记录最近 m 次分支的结果（T/NT）
- 全局历史的 m 位 + 分支 PC 低位 → 索引一个包含 $2^m$ 组 n 位预测器的表
- 表中每个条目是一个 n 位饱和计数器

**工作原理（以 (2,2) 预测器为例）**：
- 全局历史寄存器有 2 位，可以是 00/01/10/11（4种组合）
- 每个分支有 4 个独立的 2-bit 预测器，根据全局历史选择一个
- 执行结果后更新对应的 2-bit 计数器，并左移全局历史寄存器

**表大小**：$(m, n)$ 预测器需要 $2^m \times n$ 位 per 分支（若有多个分支共享则更少）。

### 5.3 (2,2) 预测器示例

分支 b2 在两次执行中：

| 全局历史 | b2 对应的2-bit预测器初始状态 | 效果 |
|----------|--------------------------|------|
| 00（b1 跳转）| NT（不跳转）→ 正确！ | — |
| 01（b1 不跳转）| NT（不跳转）→ 正确！ | 因为 b1 不跳转表示 d=1 |

→ 使用相关历史后可以**完全正确预测** b2。

### 5.4 精度比较

在相同的总位数下，相关预测器 **(2,2)** 显著优于单纯 2-bit 预测器：

| 预测器 | 总大小 | 误预测率 |
|--------|--------|---------|
| 2-bit BHT（4K项）| 8K bits | 约 10%（某些程序） |
| (2,2) 相关预测器 | 8K bits | 约 7% |

→ 相同硬件代价下，相关预测器精度更高。

## 六、竞赛预测器（Tournament Predictor）★

### 6.1 动机

2-bit 和相关预测器各有所长：
- **全局预测器**（相关预测器）：对相关性强的分支效果好
- **局部预测器**（独立 BHT）：对规律性强的循环效果好

**竞赛预测器**：同时运行多个预测器，用**选择器**决定采用哪个预测器的结果。

### 6.2 Alpha 21264 竞赛预测器

Alpha 21264 的分支预测器是业界最精细的设计之一：

**三个组件**：

#### ① 选择器（Selector）
- 4K 个 2-bit 计数器，用**全局历史（最近 12 次分支结果）** 索引
- 0/1 表示选择全局预测器；2/3 表示选择局部预测器
- 每次预测后：若局部正确/全局错误 → 计数器+1；若全局正确/局部错误 → 计数器-1

#### ② 全局预测器（Global Predictor）
- 4K 个 2-bit 预测器（标准饱和计数器）
- 用**最近 12 次全局分支历史**（12位）索引
- 12 位历史允许发现长度达 12 的分支模式

#### ③ 局部预测器（Local Predictor，二级结构）
- **一级**：1K × 10-bit 局部历史表（每个分支有独立的 10-bit 历史）
- **二级**：1K × 3-bit 饱和计数器（用局部历史索引，提供预测）

**总大小**：
$$4K \times 2 + 4K \times 2 + 1K \times 10 + 1K \times 3 = 29\text{Kbits} \approx 180,000 \text{ 个晶体管}$$

**效果**：大多数浮点程序使用全局预测器（高相关性），整数程序两者都有使用。

## 七、分支目标缓冲（Branch Target Buffer, BTB）

### 7.1 问题

即使预测"跳转"，也不知道**跳转目标地址**！处理器必须等到目标地址计算完成才能取指 → 仍有延迟。

### 7.2 BTB 结构

**分支目标缓冲（Branch Target Buffer）** 是一个小型 Cache，存储已知分支指令的目标地址：

| 字段 | 内容 |
|------|------|
| 标签（Tag）| 分支指令的 PC 地址 |
| 目标地址（Target）| 该分支的跳转目标地址 |
| 预测位（Prediction）| 2-bit 饱和计数器 |

**工作流程**：
1. 取指阶段：用 PC 查找 BTB
2. 若命中（该地址是已知分支）且预测"跳转" → **立即使用存储的目标地址取指**（无需等待）
3. 若命中但预测"不跳转" → 按顺序取下一条指令
4. 若未命中 → 按非分支处理，等到检测到分支后再更新 BTB

**注意**：BTB 中必须进行地址比较（确认是同一分支），否则可能用错误的分支地址取指。

### 7.3 BTB 变体

- **分支目标缓存（Branch Target Cache）**：只存储"预测跳转"的分支，使用内容寻址存储器（CAM）
- **存储指令的 BTB**：直接存储目标处的指令，跳过一次指令缓存访问
- **多路径 BTB**：同时缓存跳转和不跳转两个方向的指令

## 八、集成取指单元（Integrated Instruction Fetch Unit）

随着处理器每周期执行多条指令（超标量），取指成为瓶颈。现代处理器将多个取指相关功能集成为一个统一模块：

- **集成分支预测**：预测与取指同时进行
- **指令预取（Instruction Prefetch）**：提前从 Cache 取指令
- **指令内存访问和缓冲**：多路取指，填充指令缓冲区

## 九、返回地址预测器（Return Address Predictor）

### 9.1 间接跳转的问题

**间接跳转（Indirect Jump）**：目标地址在运行时才知道（存储在寄存器中），每次调用可能不同。

BTB 不适合预测间接跳转（目标地址多变）。

**SPEC89 统计**：过程返回（`RET` 指令）占间接跳转的 **85%**！

### 9.2 返回地址栈（Return Address Stack）

**思路**：利用调用-返回的**栈（Stack）** 规律：

- 函数调用时（`CALL`），将返回地址**压栈**
- 函数返回时（`RET`），**弹出**栈顶作为预测的返回地址

**实现**：处理器内维护一个 8~16 项的小型硬件栈。

**精度**：SPEC 基准测试表明，8~16 项的返回地址栈可以**非常准确**地预测过程返回（图3.22 所示）。

## 十、分支预测精度综合比较

| 预测方案 | 典型误预测率 |
|----------|------------|
| 总是预测不跳转 | ~34%（平均）|
| 2-bit BHT（4K项）| ~5%~15% |
| 相关预测器 (2,2)（8K bits）| 更优 |
| 竞赛预测器（Alpha 21264 级别）| ~1%~3% |
| Profile-based 静态预测 | FP: ~9%，整数: ~15% |

**大小 vs 精度**（SPEC89）：
- 64Kbits 以上，三种方案（局部、相关、竞赛）精度均趋近于理论上限
- 小容量时（< 4Kbits），竞赛预测器优势明显

## 十一、总结

```
分支预测演进路线：

1位 BHT → 循环问题（2次误预测）
    ↓
2位 BHT → 解决循环问题（迟滞计数器）
    ↓
相关预测器 (m,n) → 利用全局历史，考虑跨分支相关性
    ↓
竞赛预测器 → 自适应选择全局/局部预测器
    ↓
BTB → 解决目标地址延迟（直接存储跳转目标）
    ↓
返回地址栈 → 专门针对间接跳转（函数返回）
```

**关键设计指标**：
- **预测精度**：误预测率越低越好（每 1% 误预测 × 数十周期惩罚 = 巨大性能损失）
- **访问延迟**：预测器必须在一个时钟周期内给出结果
- **硬件代价**：面积（晶体管数量）
- **更新延迟**：分支结果出来后多快能更新预测器

**为什么分支预测如此重要？**

现代超标量处理器每周期可发射 3~6 条指令，流水线深度 10~20 级。一次分支误预测的代价 = **10~20 周期 × 3~6 条指令/周期 ≈ 30~120 条指令的机会成本**！高精度分支预测是现代高性能处理器的关键技术之一。
