## 二、主存组织与带宽优化（§5.8）

### 2.1 主存性能的两个维度

| 性能指标 | 含义 | 优化难度 |
|----------|------|----------|
| **延迟（Latency）** | 从发出读请求到数据返回的时间 | **难以降低**（受物理限制） |
| **带宽（Bandwidth）** | 单位时间能传输的数据量 | **较容易提升**（通过组织方式）|

- Cache 主要关心**延迟**（缺失惩罚）
- I/O 和多核系统主要关心**带宽**

### 2.2 基准：简单内存组织的性能

**假设条件**：
- 块大小 = 4 字（每字 8 字节）
- 每次内存访问：发送地址 4 周期，内存访问时间 56 周期，返回数据 4 周期
- 每次只传一个字

$$\text{缺失惩罚} = 4 \times (4 + 56 + 4) = 256 \text{ 周期}$$

$$\text{带宽} = \frac{4 \text{ 字} \times 8 \text{ 字节}}{256 \text{ 周期}} = 0.125 \text{ 字节/周期}$$

这是最低效的配置，以下三种技术逐步改善。

---

### 2.3 技术一：宽主存（Wider Main Memory）

**方案**：将内存总线和内存宽度**加倍或增加四倍**，每次传输更多数据。

**效果**（以 4 字块为例）：

| 主存宽度 | 传输次数 | 缺失惩罚 | 带宽提升 |
|----------|----------|----------|----------|
| 1字（基准）| 4次 | 256 周期 | 1× |
| 2字 | 2次 | $2 \times (4+56+4) = 128$ 周期 | 2× |
| 4字 | 1次 | $1 \times (4+56+4) = 64$ 周期 | 4× |

**缺点**：
- 总线宽度变化需要 MUX（多路选择器），增加关键路径延迟
- 增加客户购买内存的最小增量（灵活性降低）
- 复杂化错误纠正（ECC）逻辑

---

### 2.4 技术二：交错内存（Interleaved Memory）

**方案**：将内存分成多个**独立的存储体（Bank）**，用同一套总线和 Cache，但允许多个 Bank **并行读取**。

**工作原理**：
- 连续地址分布在不同 Bank（Bank 0 存地址 0,4,8...；Bank 1 存 1,5,9...）
- 发出地址后，4个 Bank 同时开始访问
- 每个 Bank 陆续返回数据，流水线式传回 CPU

**效果**（4路交错，4字块）：
$$\text{缺失惩罚} = 4 + 56 + (4 \times 4) = 76 \text{ 周期}$$

（发地址4周期 + 等待第一个Bank返回56周期 + 4个Bank陆续返回4×4=16周期）

带宽 = $\frac{32 \text{字节}}{76 \text{周期}} \approx 3.4 \times$ 基准

**设计原则**：Bank 数量应满足：
$$\text{Bank数} \geq \text{访问一个 Bank 的周期数}$$

#### 综合例题（例14）

基准：块大小1字，缺失率3%，缺失惩罚64周期，每条指令1.2次内存访问，基础CPI=2

$$CPI_{base} = 2 + 1.2 \times 3\% \times 64 = 4.30$$

增大块大小到2字（缺失率降至2%）：

| 方案 | 缺失惩罚计算 | CPI |
|------|-------------|-----|
| 64位总线，无交错 | 2×64=128周期 | 2+1.2×2%×128=5.07（变差！）|
| 64位总线，4路交错 | 4+56+8=68周期 | 2+1.2×2%×68=3.63 |
| 128位总线，无交错 | 1×64=64周期 | 2+1.2×2%×64=3.54 |

→ **单纯增大块大小反而会降低性能**，必须配合宽内存或交错！

增大块大小到4字（缺失率降至1.2%）：

| 方案 | CPI |
|------|-----|
| 64位，无交错 | 5.69（最差）|
| 64位，4路交错 | 3.09（最佳！）|
| 128位，无交错 | 3.84 |

→ **交错内存 + 大块大小** 是最佳组合（比基准快 1.39 倍）。

---

### 2.5 技术三：独立内存 Bank（Independent Memory Banks）

**进一步扩展**：每个 Bank 有**独立的内存控制器、地址线和数据总线**，允许完全异步并行访问，不限于顺序地址。

**Bank 冲突问题**：

若多个地址映射到同一 Bank，就会产生**Bank 冲突（Bank Conflict）**，导致串行化。

**例题15**：
```c
int x[256][512];
for (j = 0; j < 512; j++)
  for (i = 0; i < 256; i++)
    x[i][j] = 2 * x[i][j];
```

若有 128 个 Bank（交错粒度为 1 字），则：
- `x[0][0]`, `x[1][0]`, ..., `x[127][0]` 分别在 Bank 0~127
- `x[128][0]` 回到 Bank 0（因为 512 × 4字节 = 2048 字，是 128 的整数倍）
- 列遍历时，所有元素都落入同一个 Bank → **完全串行化！**

**解决方案**：

| 方法 | 描述 |
|------|------|
| **软件方案（编译器）** | 循环交换（访问顺序改为行优先）或填充数组使其不是 $2^n$ 整数倍 |
| **硬件方案** | 使用**素数个 Bank**（如 $2^n - 1$），使连续地址均匀分布 |

## 三、内存技术（§5.9）

### 3.1 两个关键指标

| 指标 | 定义 |
|------|------|
| **访问时间（Access Time）** | 从发出读请求到所需数据到达的时间 |
| **周期时间（Cycle Time）** | 两次内存访问之间的最小间隔时间（通常 > 访问时间，因为地址线需要稳定）|

### 3.2 SRAM vs DRAM

| 特性 | SRAM（静态随机存储器）| DRAM（动态随机存储器）|
|------|---------------------|---------------------|
| 用途 | Cache | 主存（Main Memory）|
| 刷新需求 | **不需要**刷新 | 需要**定期刷新**（约每8ms一次，占用约1%时间）|
| 每bit晶体管数 | **6个**（由交叉耦合反相器构成）| **1个**（电容+晶体管）|
| 容量/面积 | 较小（密度低）| 较大（密度高，**4~8倍**）|
| 成本 | **8~16倍** 更贵 | 便宜 |
| 访问速度 | 快 | 慢 |

**DRAM 地址复用**：为了减少引脚数，DRAM 将地址分为两半：
- **RAS（Row Address Strobe，行地址选通）**：先发送行地址
- **CAS（Column Access Strobe，列地址选通）**：再发送列地址

内存芯片内部组织为**二维矩阵**，行地址选择"行"，列地址选择"列"，两者结合确定单元位置。

### 3.3 DRAM 的演进

| 类型 | 特点 |
|------|------|
| **FPM DRAM**（Fast Page Mode）| 同一行内多次访问只需发一次行地址 |
| **EDO DRAM**（Extended Data Out）| 在上次数据输出期间就可以发送下次的列地址 |
| **SDRAM**（Synchronous DRAM）| 与系统时钟同步，支持突发传输（Burst Mode）|
| **DDR SDRAM**（Double Data Rate）| 时钟上升沿和下降沿都传数据，带宽翻倍 |

### 3.4 嵌入式系统的存储器：ROM 和 Flash

嵌入式系统通常**没有磁盘**，用以下非易失性存储器代替：

| 类型 | 可写性 | 特点 |
|------|--------|------|
| **ROM**（掩膜式）| 出厂时编程，**不可修改** | 最便宜，适合大批量生产 |
| **PROM**（熔丝式）| **一次可编程** | 比 ROM 灵活 |
| **EPROM** | 可用紫外线擦除，可重写 | 需专用设备 |
| **EEPROM** | 可电擦除，字节为单位 | 灵活但贵 |
| **Flash Memory** | 可电擦除，扇区为单位 | 读接近DRAM速度，**写慢 10~100 倍** |

Flash 是移动设备、嵌入式系统（如智能手机、路由器）的主存储介质，也是 SSD 的核心技术。

## 四、虚拟内存（§5.10）

### 4.1 虚拟内存的动机

**问题**：程序想要：
1. 比物理内存更大的地址空间
2. 地址空间连续（不管实际物理内存是否连续）
3. 与其他程序相互隔离（内存保护）

**解决方案——虚拟内存（Virtual Memory）**：
- 操作系统和硬件共同提供**虚拟地址空间**的抽象
- 程序运行在"假想的"大内存中
- 实际只有部分数据驻留内存，其余在磁盘上

**优势**：
- 程序不需要管理物理内存（由 OS 负责）
- 支持多程序同时运行（多道程序设计/Time-Sharing）
- 提供内存保护（进程间隔离）
- 无需购买大量 RAM

### 4.2 虚拟内存的工作原理

```
程序启动 → OS 将程序（部分）载入RAM
       ↓
程序访问未载入的地址（页缺失 Page Fault）
       ↓
OS 从磁盘读取所需页面 → 若内存满，先驱逐某页（写回磁盘如果脏）
       ↓
更新页表 → 程序继续执行
```

**关键术语对照**（Cache vs 虚拟内存）：

| Cache 术语 | 虚拟内存术语 |
|-----------|------------|
| 块（Block）| 页（Page）/ 段（Segment）|
| Cache 缺失（Miss）| 页缺失（Page Fault）|
| 地址映射 | 内存映射 / 地址翻译 |
| 主存 | 物理内存（Physical Memory）|
| 磁盘 | 下一级存储 |

### 4.3 分页 vs 分段

| 方式 | 块大小 | 优点 | 缺点 |
|------|--------|------|------|
| **分页（Paging）** | **固定大小**（如 4KB）| 内存管理简单，无外部碎片 | 有内部碎片（最后一页未用满）|
| **分段（Segmentation）** | **可变大小** | 符合程序逻辑结构 | 有外部碎片，管理复杂 |

现代系统通常使用**分页**（或分页+分段的混合方式）。

### 4.4 虚拟内存的四问框架

虚拟内存也可以用 Cache 设计的四问框架来理解：

#### Q1：页面放置策略

- 缺失惩罚极高（访问磁盘需要数百万周期）
- 因此缺失率必须极低 → 使用**全相联（Fully Associative）**策略
- 操作系统允许页面放到**物理内存中的任意位置**

#### Q2：如何找到页面（页表）

**页表（Page Table）**：一个数组，下标为**虚拟页号（VPN）**，内容为对应的**物理页号（PPN）**。

- 虚拟地址 = 虚拟页号（VPN）+ 页内偏移（Page Offset）
- 物理地址 = 物理页号（PPN）+ 页内偏移（不变！）

**页表大小估算**：
$$\text{页表大小} = \frac{\text{虚拟地址空间}}{\text{页大小}} \times \text{每项字节数}$$

例：32位虚拟地址，4KB页大小，每项4字节：
$$\frac{2^{32}}{2^{12}} \times 4 = 2^{20} \times 4 = 4\text{MB}$$（每个进程都需要这么大的页表！）

**优化**：
- **哈希页表 / 反向页表（Inverted Page Table）**：以物理页为索引，大小 = 物理页数 × 每项大小（更小）
- **TLB（Translation Lookaside Buffer）**：缓存最近使用的页表项，避免每次访存都查页表（见§5.7）

```
地址翻译过程：
虚拟地址 → TLB 查找
    ↓命中              ↓缺失
直接得到物理地址    查页表 → 更新TLB → 得到物理地址
                      ↓若页不在内存
                   触发Page Fault → OS处理
```

#### Q3：页面替换策略

- OS 尽量使用 **LRU（最近最少使用）** 策略
- 硬件提供**使用位（Use Bit / Reference Bit）**：页面被访问时置1
- OS 定期清零使用位，通过观察哪些页使用位为0来估算最近未用页
- 写脏位（Dirty Bit）决定驱逐时是否需要写回磁盘

#### Q4：写策略

- 磁盘访问需要数百万周期 → **绝对不能使用写通（Write-Through）**
- 虚拟内存**始终使用写回（Write-Back）**
- **脏位（Dirty Bit）**：记录该页是否被修改
  - 脏 → 驱逐时必须写回磁盘
  - 未脏 → 驱逐时直接丢弃（磁盘上还有最新副本）

## 五、总结

### 存储层次全景

```
寄存器（~1周期）
    ↓
L1 Cache（~3-5周期）: SRAM，分离I/D，32~64KB
    ↓
L2 Cache（~10-20周期）: SRAM，统一，256KB~8MB
    ↓
L3 Cache（~30-50周期）: SRAM，统一，4~32MB
    ↓
主存 DRAM（~100-300周期）
    ↓
磁盘/SSD（~100万周期）
```

### 主存带宽优化三技术

| 技术 | 核心思路 | 效果 |
|------|----------|------|
| 宽主存 | 一次传更多位 | 带宽正比于宽度 |
| 交错内存 | 多 Bank 并发 | 大幅降低缺失惩罚 |
| 独立内存Bank | 独立控制器，无序访问 | 最大带宽，但复杂 |

### 虚拟内存 = 磁盘的 Cache

| 设计维度 | 选择 | 原因 |
|----------|------|------|
| 放置策略 | 全相联 | 缺失惩罚太高，必须最大化命中率 |
| 替换策略 | LRU（近似）| OS 用使用位估算 |
| 写策略 | 写回 | 磁盘写太慢 |
| 块大小 | 页 4KB~2MB | 平衡碎片与缺失率 |
