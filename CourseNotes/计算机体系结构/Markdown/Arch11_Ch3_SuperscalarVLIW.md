## 一、回顾：ILP 硬件技术路线

前几章建立的 ILP 技术栈：

| 技术 | 目标 |
|------|------|
| 基本 5 级流水线 + 转发 | 减少数据冒险停顿 |
| 延迟分支 | 减少控制停顿 |
| 记分牌（Scoreboard）| 减少真数据依赖停顿 |
| Tomasulo 算法 | 通过重命名消除 WAR/WAW 停顿，乱序执行 |
| 分支预测器 | 减少控制停顿 |
| 硬件投机执行（ROB）| 允许越过分支投机执行 |

以上技术目标：实现**理想 CPI = 1**。但 CPI = 1 是单发射流水线的极限。要进一步提高，需要**每个时钟周期发射多条指令（CPI < 1，等价于 IPC > 1）**。

---

## 二、多发射处理器：获得 CPI < 1 ★

### 2.1 多发射处理器分类

| 类型 | 发射数 | 调度方式 | 代表 |
|------|--------|---------|------|
| **静态超标量（Static Superscalar）** | 1~8 条/周期，可变 | 编译器辅助 | 早期 MIPS R10000 |
| **动态超标量（Dynamic Superscalar）** | 1~8 条/周期，可变 | 硬件（Tomasulo） | Intel Pentium III/4 |
| **投机超标量（Speculative Superscalar）** | 1~8 条/周期，可变 | 硬件 + ROB 投机 | IBM PowerPC, Alpha |
| **VLIW（超长指令字）** | 4~16 条/周期，固定 | 编译器 | Intel IA-64（EPIC）|

**EPIC（Explicitly Parallel Instruction Computer）**：IA-64 的别名，是 VLIW 的工业化版本。

---

## 三、静态超标量（Statically Scheduled Superscalar）

### 3.1 基本原理

- 指令按**程序顺序（In-Order）发射**
- 发射时检查所有流水线冒险
- 每周期可以发射 0~N 条指令（取决于冒险情况）
- **发射包（Issue Packet）**：取指单元送来的一组指令，可能同时发射

### 3.2 发射阶段的两步流水线

1. **第一步**：决定发射包内哪些指令可以同时发射（检测包内冒险）
2. **第二步**：检测所选指令与已发射指令之间的冒险（检测包间冒险）

### 3.3 双发射流水线示例（MIPS 风格）

**约束**：
- 同时发射 1 条整数指令（左槽）+ 1 条浮点指令（右槽）
- 每周期取 64 位（两条 32 位指令）
- 只有第一条指令能发射时，第二条才能发射
- FP 寄存器需要更多读写端口

**1 周期 Load 延迟扩大效应**：
- 单发射：Load 后 1 条指令不能使用结果
- 双发射：Load 后 **3 条**指令（右半部分 + 下一个发射槽两条）都不能使用结果

## 四、多发射的挑战 ★

### 4.1 发射复杂度

- **N 发射**：需要检查 $O(N^2 - N)$ 对指令之间的冒险 → 随 N 增大，逻辑复杂度急剧上升
- 发射阶段通常需要**分级流水**（拆成多个子周期），但这会增加分支惩罚

### 4.2 寄存器堆端口数

- **N 发射**需要：读端口 ≥ $2N$，写端口 ≥ $N$
- 端口数量增加 → 寄存器堆面积和延迟都增加

### 4.3 寄存器重命名复杂度（最棘手！）

考虑 4 路发射时，**同一个时钟周期内可能对同一寄存器写多次**：

```asm
add r1, r2, r3    → 重命名为 add p11, p4, p7
sub r4, r1, r2    → 重命名为 sub p22, p11, p4   (r1 依赖上条！)
lw  r1, 4(r4)     → 重命名为 lw  p23, 4(p22)   (r1 再次被写！)
add r5, r1, r2    → 重命名为 add p12, p23, p4  (r1 依赖上条！)
```

**必须在单个时钟周期内完成全部 4 条指令的重命名**，且正确处理包内依赖 → 硬件实现极其复杂。

### 4.4 结果总线（Result Bus）

多条指令同时完成 → 需要**多条 CDB**（或多路转发路径），每条保留站都需要监听所有总线 → 面积和功耗大幅增加。

## 五、动态超标量（Dynamically Scheduled Superscalar）

### 5.1 扩展 Tomasulo 支持多发射

**两种解决方案**：
1. **半周期流水（Half-Clock Pipeline）**：将发射逻辑运行在半个周期，从而每个完整时钟周期可以处理两条指令
2. **宽化发射逻辑（Widen Issue Logic）**：直接构建处理两条指令（含包内依赖）的硬件逻辑

现代超标量通常**两种方案并用**。

### 5.2 双发射 Tomasulo 示例（无投机）

**假设**：
- 每周期最多 1 条 FP 操作 + 1 条整数操作（即使它们有依赖）
- 一个整数功能单元（ALU + 地址计算）
- 独立的分支条件评估单元
- 分支单发射，完美预测
- 无投机：分支解决前，后续指令不发射

**延迟假设**：
- 整数 ALU：1 周期
- Load：2 周期
- FP 加法：3 周期

结果：整数功能单元成为**瓶颈**（ALU 和地址计算共用一个单元）。改进：为 ALU 和地址计算**分配独立功能单元** → 需要第二条 CDB！

### 5.3 多发射 + 投机

结合 ROB：
- 每周期可以提交多条指令
- 分支预测错误时刷新整个 ROB（和单发射一样）
- 示例循环（5 条指令）在双发射 + 投机时可以将每次迭代的时钟周期数从 8 减少到约 4~5

## 六、编译器 ILP 技术：循环展开（Loop Unrolling）★

编译器可以通过**循环展开（Loop Unrolling）** 静态暴露更多 ILP。

### 6.1 基本循环

```c
for (i = 1000; i > 0; i--) x[i] = x[i] + s;
```

**MIPS 代码（原始）**：
```asm
Loop: LD    F0, 0(R1)      ; 加载 x[i]
      ADDD  F4, F0, F2     ; x[i] + s
      SD    0(R1), F4      ; 存储结果
      SUBI  R1, R1, #8     ; i--
      BNEZ  R1, R2, Loop   ; 继续循环
```

**有冒险（stall）的执行**：每次迭代约 10 个时钟周期（有多个停顿）。

**经过调度（避免停顿）**：每次迭代约 6 个时钟周期。

### 6.2 展开 4 次后优化

**展开 4 次，避免停顿的优化版本**（将不同迭代的 Load/计算/Store 交织）：

```asm
Loop: LD    F0, 0(R1)       ; 迭代 1
      LD    F6, -8(R1)      ; 迭代 2
      LD    F10, -16(R1)    ; 迭代 3
      LD    F14, -24(R1)    ; 迭代 4
      ADDD  F4, F0, F2
      ADDD  F8, F6, F2
      ADDD  F12, F10, F2
      ADDD  F16, F14, F2
      SD    0(R1), F4
      SD    -8(R1), F8
      SUBI  R1, R1, #32
      SD    +16(R1), F12    ; 注意偏移量调整
      BNEZ  R1, LOOP
      SD    8(R1), F16      ; 8-32 = -24
```

**结果**：14 个时钟周期 / 4 次迭代 = **3.5 CPI/迭代**（原来 10 → 3.5，近 3 倍加速）。

### 6.3 循环展开的关键步骤（编译器执行）

1. 确认循环迭代独立（检查内存地址是否有重叠）
2. **寄存器重命名**（将每次迭代的 F0/F4 重命名为 F0/F6/F10/F14 等）→ 消除名称依赖
3. 消除冗余的循环控制指令（SUBI + BNEZ）
4. 检查 Load/Store 是否可以交换顺序（内存消歧）
5. 调度代码，保留必要的数据依赖

### 6.4 循环展开的代价

| 代价 | 说明 |
|------|------|
| 代码膨胀 | 开销比例：2/6 → 2/14 → 2/26（随展开次数改善） |
| 寄存器压力 | 需要更多寄存器保存临时值 |
| 不适合非循环分支 | 对 if-else 结构效果有限 |
| 不知道上界 | 编译器处理：生成两个循环（前者处理余数，后者处理主体）|

## 七、VLIW（超长指令字）★

### 7.1 基本概念

**VLIW（Very Long Instruction Word）**：每条"指令"包含多个独立操作的显式编码。

- 编译器负责找出可并行执行的操作，填入一条宽指令
- 由定义，同一 VLIW 指令中的操作**全部独立** → 可以并行执行
- 典型宽度：2 整数 + 2 FP + 2 内存 + 1 分支 = 7 操作 × 16~24 位 = **112~168 位/指令**

VLIW 别名：
- **EPIC**（Explicitly Parallel Instruction Computer）—— Intel IA-64 的名称
- **LIW**（Long Instruction Word）——更通用的叫法
- Transmeta 处理器称之为"分子（Molecule）"，每个操作称为"原子（Atom）"

### 7.2 VLIW 循环展开示例

展开 7 次，利用双内存访问 + 双 FP 操作 + 1 整数/分支：

| 周期 | 内存1 | 内存2 | FP操作1 | FP操作2 | 整数/分支 |
|------|-------|-------|---------|---------|----------|
| 1 | LD F0,0(R1) | LD F6,-8(R1) | — | — | — |
| 2 | LD F10,-16(R1) | LD F14,-24(R1) | — | — | — |
| 3 | LD F18,-32(R1) | LD F22,-40(R1) | ADDD F4,F0,F2 | ADDD F8,F6,F2 | — |
| 4 | LD F26,-48(R1) | — | ADDD F12,F10,F2 | ADDD F16,F14,F2 | — |
| 5 | — | — | ADDD F20,F18,F2 | ADDD F24,F22,F2 | — |
| 6 | SD 0(R1),F4 | SD -8(R1),F8 | ADDD F28,F26,F2 | — | — |
| 7 | SD -16(R1),F12 | SD -24(R1),F16 | — | — | — |
| 8 | SD -32(R1),F20 | SD -40(R1),F24 | — | — | SUBI R1,#48 |
| 9 | SD 0(R1),F28 | — | — | — | BNEZ Loop |

**结果**：7 次迭代 / 9 个时钟周期 = **1.3 CPI/迭代**，平均 2.5 操作/周期（50% 利用率）。

注意：VLIW 需要 **15 个寄存器**（vs. 超标量的 6 个）。

### 7.3 VLIW 的问题

**技术问题**：
1. **代码膨胀（Code Size）**：循环展开 + 大量空操作（NOP）填充未使用的功能单元槽
2. **锁步操作限制（Lockstep Operation）**：任何一个功能单元停顿 → 整个处理器停顿（无动态调度）

**逻辑问题**：
3. **二进制兼容性（Binary Code Compatibility）**：VLIW 指令直接编码并行性 → 不同实现（不同功能单元数）需要不同编译；更换处理器必须重新编译所有程序

## 八、高级编译器 ILP 支持技术（简介）

| 技术 | 原理 |
|------|------|
| **软件流水（Software Pipelining）** | 符号化循环展开：将不同迭代的指令交织，构成一个"最优"循环体 |
| **全局代码调度（Global Code Scheduling）** | 跨越分支边界移动指令 |
| **踪迹调度（Trace Scheduling）** | 将最可能执行的路径（踪迹）作为整体调度对象 |
| **超级块（Superblock）** | 踪迹调度的简化版（单入口、多出口的指令序列）|

## 九、案例：Intel Pentium Pro（P6）

### 9.1 解决 80x86 复杂指令的方案

80x86 指令长度不固定（1~17 字节），直接流水线化极其复杂。P6 的解决方案：

**将 80x86 指令翻译为 72 位"微操作（micro-ops）"**，再流水线化微操作：
- 大多数指令翻译为 1~4 条微操作
- 复杂指令由 8K × 72 位微程序（Microprogram）翻译为长微操作序列
- 微操作格式类似 RISC（类 MIPS）

### 9.2 P6 关键参数

| 参数 | 数值 |
|------|------|
| 每周期最多发射（80x86）| 3 条 |
| 每周期最多执行完成 | 5 条微操作 |
| 每周期最多提交 | 3 条微操作 |
| ROB 窗口大小 | 40 条指令 |
| 保留站数 | 20 个 |
| 重命名寄存器数 | 40 个 |
| 整数 FU 数 | 2 |
| 浮点 FU 数 | 1 |
| 内存 FU | 1 Load + 1 Store |

### 9.3 P6 流水线（14 级）

- **前端（8级，顺序）**：取指（16B/周期）→ 译码（3指令/周期）→ 重命名（3微操作/周期）
- **执行（3级，乱序）**：5 个独立功能单元中的乱序执行
- **提交（3级，顺序）**：按程序顺序提交（通过 ROB），3 微操作/周期

## 十、总结

```
多发射处理器的设计权衡：

静态超标量/VLIW
  优点：硬件简单，功耗低
  缺点：编译器难以充分发掘 ILP；二进制兼容性差（VLIW）

动态/投机超标量
  优点：运行时发掘 ILP；对编译器透明；二进制兼容
  缺点：硬件非常复杂；功耗大；发射宽度受限（O(N²) 检查）
```

**IPC 上限**：对于真实程序（大量控制流、内存访问延迟），实际 IPC 远低于理论发射宽度。
- 4 路超标量的实际 IPC 通常只有 1~2（而非理论上的 4）
- 限制因素：控制依赖（分支）、内存延迟（Cache 缺失）、数据依赖

> **下一章**将介绍**多线程（Multithreading）**——通过多个线程共享硬件资源，进一步提高处理器利用率，填补 Cache 缺失和分支预测错误导致的流水线空泡。
