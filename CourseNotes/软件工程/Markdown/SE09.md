# Chapter 9 Requirements Modeling: Scenario-Based Methods

## Requirements Analysis
需求分析的目标是把“客户想要什么”说清楚。

- describe what the customer requires
- establish a basis for software design
- define requirements that can be validated

## A Bridge
analysis model 是系统描述和设计模型之间的桥梁。

- system description
- analysis model
- design model

## Rules of Thumb
分析模型要抓业务，不要过早陷入技术细节。

- focus on visible business-domain requirements
- keep abstraction high
- minimize coupling
- keep the model simple
- provide value to all stakeholders

## Domain Analysis
领域分析的目标是提炼可复用的通用需求。

- identify common requirements in a domain
- use technical literature, existing applications, surveys, expert advice
- build a domain analysis model

## Scenario-Based Modeling
场景模型通常从用例开始。

- use-cases
- use-case diagrams
- activity diagrams
- swim lane diagrams

## Use-Cases
用例描述系统的一条使用路径。

- actors represent people or devices
- one actor may play multiple roles
- use-cases help answer what to write and how much detail is needed

## Developing and Reviewing Use-Cases
写用例时要同时考虑主流程和替代流程。

- main tasks and system information
- changes in external environment
- desired information from the system
- error conditions and alternate behaviors

## Activity and Swim Lane Diagrams
活动图和泳道图把用例流程画出来。

- activity diagram shows procedural flow
- swim lane diagram shows responsibility by actor or analysis class

## Example: Access Camera Surveillance
案例说明如何把“看摄像头”这种任务拆成流程。

- valid password / ID
- thumbnail views
- select camera
- exit / switch camera
