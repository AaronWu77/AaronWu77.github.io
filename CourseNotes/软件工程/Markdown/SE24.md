# Chapter 24 Testing Object-Oriented Applications

## OO Testing Overview
OO 系统的测试不能只盯着代码，还要看模型。

- test analysis/design models for semantic errors
- unit and integration strategy must change
- test cases should reflect OO characteristics

## Correctness of OO Models
分析和设计阶段的正确性，先看它像不像真实世界。

- class definitions
- class hierarchy
- class relationships
- omission and ambiguity

## Class Model Consistency
CRC 和对象关系图要互相对照。

- check responsibilities against collaborators
- invert connections to see if dependencies make sense
- merge duplicated responsibilities when appropriate

## OO Testing Strategies
OO 测试的“unit”比传统测试更大。

- unit test the encapsulated class
- integration by thread-based / use-based / cluster testing
- validation testing uses black-box methods

## Testing Methods
常见 OO 测试方法可以从不同角度下手。

- fault-based testing
- class hierarchy testing
- scenario-based test design

## Random and Partition Testing
随机和分区测试可以覆盖更多类实例生命周期。

- random testing：生成有效的操作序列
- partition testing：按 state / attribute / category 分组
- goal 是减少用例数量但不丢覆盖

## Inter-Class and Behavior Testing
多类协作和状态变化是 OO 测试的重点。

- inter-class testing checks message passing among collaborators
- behavior testing checks state transitions
- test sequences should cover allowable states
