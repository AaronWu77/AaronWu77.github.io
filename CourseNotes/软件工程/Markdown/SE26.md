# Chapter 26 Testing Mobile Applications

## 26.1 Mobile App Testing Strategy Questions

移动应用测试一开始就要先想清楚几类策略问题：

- 是否必须先做出一个完整可运行原型，再让用户参与测试？
- 测试时应该使用用户自己的设备，还是由测试方提供设备？
- 应该覆盖哪些设备类型和用户群体？
- 什么时候适合实验室测试，什么时候适合远程测试？

这些问题决定了后续测试的设备范围、用户样本和实施方式。

---

## 26.2 Mobile Testing Guidelines

课件给出的移动测试指导原则包括：

- 理解 *network landscape* 和 *device landscape*
- 在不可控的真实环境下进行测试
- 选择合适的自动化测试工具
- 识别最关键的硬件 / 平台组合
- 至少在所有主要平台上完整检查一次端到端功能流程
- 用真实设备进行性能、GUI 和兼容性测试
- 在真实网络负载下测量性能

移动端测试尤其强调：**真机、真网、真实场景。**

---

## 26.3 Mobile App Testing

常见移动应用测试类型包括：

- **Conceptual Testing**：从概念层验证应用思路和目标
- **Unit and System Testing**：验证局部功能与系统级行为
- **User Experience Testing**：验证用户体验
- **Stability Testing**：验证稳定性
- **Connectivity Testing**：验证联网能力
- **Performance Testing**：验证性能
- **Compatibility Testing**：验证不同设备 / 系统兼容性
- **Security Testing**：验证安全性
- **Certification Testing**：验证是否满足发布 / 分发平台标准

---

## 26.4 Automated Testing

自动化测试不是直接上工具，而是需要一个逐步落地过程：

1. *Feasibility analysis*
2. *Proof of concept*
3. *Best practice test framework*
4. *Customize testing tools*
5. *Test under real world conditions*
6. *Rapid defect resolution*
7. *Reuse of test scripts*

也就是说，自动化测试的价值不仅在“自动执行”，还在于框架化、复用化和缺陷快速反馈。

---

## 26.5 Stress Test Cases

移动应用的压力测试场景往往更贴近真实设备使用环境，例如：

- 同时在一台设备上运行多个 App
- 让系统软件感染病毒或恶意软件
- 尝试接管设备并利用其传播垃圾信息
- 强迫移动应用处理异常大量事务
- 在设备中存储大量数据

这些测试重点观察应用在资源紧张、系统受污染或极端负载下是否仍然可控。

## 26.6 Mobile Usability Elements

移动应用可用性通常要从以下元素综合评估：

- **Functionality**
- **Information architecture**
- **Screen design**
- **User input mechanisms**
- **Mobile context taken into account**
- **Interface usability**
- **Trustworthiness**
- **Feedback**
- **Help facilities**

和 Web 或桌面系统相比，移动端更强调屏幕限制、输入方式和上下文环境。

---

## 26.7 Specialized Usability Tests

### 26.7.1 Specialized Usability Tests

移动端有一些需要单独评估的交互方式：

- **Gestures**
- **Voice input and recognition**
- **Virtual keyboard input**
- **Alerts and errors**

这些都是移动设备特有或更敏感的交互点，必须单独测试，否则很容易影响真实体验。

## 26.8 Mobile App Testing Tools

### 26.8.1 Mobile App Testing Tools

常见工具类别包括：

- **Mobile page compliance checkers**
- **Mobile browser emulators**
- **Device emulators**
- **Key logging and playback**
- **Network monitors**

这些工具分别用于：

- 页面规范检查

## 26.9 Summary

移动应用测试相比传统软件与 WebApp 测试，更强调以下几点：

- 设备碎片化
- 网络环境复杂
- 真机测试必要性更高
- 用户体验与交互方式影响更直接
- 发布平台的认证与分发要求更重要

因此，移动测试的核心不是只验证“能不能运行”，而是验证它能否在**不同设备、不同网络、不同真实使用环境**下稳定、可用、安全地运行。
