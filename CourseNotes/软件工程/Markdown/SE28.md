# Chapter 28 Formal Modeling and Verification

## 28.1 The Cleanroom Strategy

Cleanroom 的目标是做出“接近无缺陷”的软件。

它把开发拆成几个阶段：

1. **Formal design**：用黑盒式规格逐步细化
2. **Correctness verification**：从规格向设计和代码做正确性验证
3. **Code generation / inspection**：把规格转成代码并检查
4. **Statistical test planning**：按使用概率规划测试
5. **Statistical usage testing**：按统计样本执行测试
6. **Certification**：通过后认证增量可集成

---

## 28.2 Functional Specification

功能规格要尽量清晰、无歧义。

- 用规格语言描述系统行为
- 让后续设计和实现都能追溯到规格
- 规格本身就是后续验证的基准

---

## 28.3 Cleanroom Design

Cleanroom design 强调正确性推导，而不是靠后期调试补救。

- 先定义清晰的功能行为
- 再证明设计是否满足这些行为
- 尽量在编码前减少错误

课件想表达的核心是：**设计阶段的验证，价值高于代码阶段的补丁式修正**。

---

## 28.4 Cleanroom Testing

Cleanroom testing 不是随便挑例子测，而是按使用分布来测。

- 测试用例来自 usage probability distribution
- 通过随机样本估计可靠性
- 若无失败或失败控制在允许范围内，可进行认证

### Models

- **Sampling model**：执行随机测试样本
- **Component model**：按组件结构分析可靠性
- **Certification model**：根据整体可靠性预测是否可发布

---

## 28.5-6 Formal Methods

形式化方法是用数学手段描述、开发和验证系统。

- 规格只允许单一解释
- 语法和语义尽量精确
- 通过推理规则保证前后陈述的一致性

### Common ideas

- 用 state 描述系统状态
- 用 precondition 描述操作前条件
- 用 postcondition 描述操作完成后的结果

形式化方法的价值在于减少歧义，让“正确性”可以被证明而不只是被假设。
