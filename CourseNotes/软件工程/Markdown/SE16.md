# Chapter 16 Pattern-Based Design

## What Is a Design Pattern?
设计模式是对“问题—上下文—解决方案”的可复用描述。

- 它帮助团队复用设计知识
- 不是抽象口号，而是经过验证的方案
- 关键是把经验写下来，方便后人复用

## Basic Concepts
一个模式至少要说清三个东西。

- context：问题发生的环境
- problem：要解决的矛盾
- solution：在该环境下有效的方案

## Effective Patterns
一个有效的模式应该满足这些要求。

- 能解决具体问题
- 是被验证过的
- 解决方案不显而易见
- 描述的不只是模块，而是更深层的结构关系

## Kinds of Patterns
模式可以按层次分类。

- architectural patterns
- data patterns
- component patterns
- UI patterns
- WebApp patterns

## GoF Pattern Types
经典 GoF 模式通常分三类。

- creational patterns
- structural patterns
- behavioral patterns

## Frameworks
框架不是普通模式，而是带有插槽的可复用骨架。

- 提供通用结构
- 允许通过 hooks / slots 注入具体实现
- 适合特定问题域的快速搭建

## Pattern-Based Software Design
基于模式的设计要“先看大局，再向内收敛”。

- 先理解 requirements model
- 先找 architectural patterns
- 再找 subsystem / component patterns
- 最后细化到 UI 和局部细节

## Common Design Mistakes
模式用错，往往不是模式本身的问题，而是理解问题不够。

- 没看清问题上下文
- 选了看起来对、其实不合适的模式
- 过于字面化地套用模式

## Architectural Patterns
架构模式常常对应更大的系统结构。

- concurrency
- persistence
- distribution
- 典型例子：Kitchen pattern

## Component-Level Patterns
组件级模式解决子问题。

- 重点在功能子模块
- 常见于搜索、帮助、查询等功能
- 可直接从需求模型中提炼

## UI Patterns
UI 模式帮助我们处理常见交互问题。

- whole UI
- page layout
- forms and input
- tables
- direct manipulation
- navigation
- searching
- e-commerce

## WebApp Patterns
WebApp 模式通常围绕信息、导航、呈现和功能四个层面。

- information architecture patterns
- navigation patterns
- interaction patterns
- presentation patterns
- functional patterns

## Patterns for Mobile Apps
移动端也有自己的模式库。

- check-in screens
- maps
- popovers
- sign-up flows
- tab navigation
- invitations
- 还会涉及 MVC、pagination、sync 等实现模式
