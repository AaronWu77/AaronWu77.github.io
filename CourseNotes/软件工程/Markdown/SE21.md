# Chapter 21 Software Quality Assurance

## 21.1 Comment on Quality

质量管理的问题不在于“大家不知道质量重要”，而在于很多人**自以为已经懂了质量**，却没有真正落实。

SQA 的本质是：让质量不依赖个人自觉，而依赖过程、标准和证据。

- 质量管理的问题并非在于人们不了解它本身。问题在于他们自以为已经了解了它……在这方面，质量与性有很多相似之处。
- 每个人都支持它。（当然，在某些条件下是这样。） 
- 每个人都觉得自己理解它。（尽管他们并不愿意去解释它。） 
- 每个人都认为执行只是遵循自然倾向的问题。（毕竟，我们还是能相互适应的。） 
- 而且，当然，大多数人认为这些方面的问题是由其他人造成的。（如果他们愿意花时间把事情做好就好了。）

---

## 21.2 Elements of SQA

SQA 不只是“检查代码”，而是覆盖整个软件过程。

- 风险管理
- 质量计划
- 过程审查
- 度量与分析
- 缺陷跟踪
- 质量保证活动的闭环控制

---

## 21.4.1 SQA Tasks

SQA 组需要检查软件过程和工作产品是否符合：

- 组织政策
- 内部软件标准
- 外部标准（如 ISO-9001）
- 项目计划中的规定

同时还要确保：

- 偏离标准的情况被记录
- noncompliance items 被持续跟踪，直到关闭

---

## 21.4.2 SQA Goals

SQA 关注的不是单点错误，而是质量基础是否扎实。

- **Requirements quality**：需求是否正确、完整、一致
- **Design quality**：设计是否高质量
- **Code quality**：代码及相关工作产品是否符合编码标准
- **Quality control effectiveness**：有限资源是否被用在最可能提升质量的地方

## 21.6 Statistical SQA

统计化 SQA 的思路是用度量驱动改进。

- 收集过程和产品数据
- 找出错误与缺陷的根因
- 用 Pareto principle 聚焦“少数关键原因”
- 优先修复最主要的质量来源

### Six-Sigma for Software Engineering

Six Sigma 强调用数据衡量过程能力，并持续降低缺陷率。

典型步骤包括：

1. measure
2. analyze
3. improve
4. control

---

## 21.7 Reliability and Safety

### 21.7.1 Software Reliability

可靠性关注软件在一段时间内无故障运行的能力。

- 课件把可靠性和 `MTBF / MTTF / MTTR` 联系起来
- 核心是衡量故障之间的平均间隔、恢复时间以及可用性

### 21.7.2 Software Safety

安全性关注潜在危险是否被识别并控制。

- 早期识别 hazards
- 在设计中加入控制措施
- 尽量避免危险进入运行阶段

---

## 21.8 ISO 9001:2008 Standard

ISO 9001 关注的是质量管理体系是否建立并可追踪。

涉及内容包括：

- management responsibility
- quality system
- contract review
- design control
- document and data control
- process control
- inspection and testing
- corrective and preventive action
- internal quality audits
- training
- statistical techniques
