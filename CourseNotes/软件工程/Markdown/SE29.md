# Chapter 29 Software Configuration Management

## 29.1 The Need for SCM

软件一定会变，SCM 要做的是让变化可控。

- 代码会变
- 文档会变
- 数据会变
- 需求也会变

---

## 29.2 What Are These Changes?

变化可能来自多个层面：

- business requirements
- user requirements
- technical requirements
- software models
- project plan
- test artifacts

因此 SCM 不只是管源码，还要管与软件相关的整个配置集合。

---

## 29.3 Software Configuration

software configuration 通常由以下部分组成：

- programs
- documents
- data

这些都是配置对象的一部分。

---

## 29.4 Baselines

baseline 是经过正式评审并被认可的工作产品版本。

- 之后的修改都基于 baseline 进行
- 它是后续开发和发布的基准点
- 没有 baseline，版本管理就会失去锚点

---

## 29.5 Configuration Objects

配置对象是 SCM 管理的最小单位。

- 源码
- 文档
- 数据文件
- 配置项

管理目标是让每个对象的版本、状态和变更历史都可追踪。

---

## 29.6 SCM Repository

SCM repository 是整个配置管理的核心。

- 存放配置对象及其历史版本
- 支持变更管理
- 支持版本回退
- 支持发布和审计

---

## 29.7 Version Control

版本控制让团队可以并行修改而不互相覆盖。

- 保存对象的多个版本
- 提供构建和发布支持
- 记录版本之间的关系

---

## 29.8 Change Control

change control 用来管理变更申请、审批和执行。

### Typical process

1. assign people to SCIs
2. check out SCIs
3. make the change
4. review / audit the change
5. establish a baseline for testing
6. run SQA and testing
7. promote the SCI for release
8. check in the changed SCIs

---

## 29.9 Auditing and Status Accounting

### Auditing

审计检查变更是否真的按流程完成。

### Status Accounting

状态记账记录：

- 哪些 SCIs 被改了
- 变更请求到哪一步了
- 当前版本状态是什么

---

## 29.10 SCM for Web and Mobile

Web / Mobile App 的内容类型更多，所以 SCM 更复杂。

- text
- graphics
- scripts
- audio / video
- forms

必须把这些内容组织成合理的 configuration objects，并配合 change control。

### Content Management

- **collection subsystem**：收集或创建内容
- **publishing subsystem**：转换、格式化并发布内容
- **database capabilities**：搜索和定位内容对象
- **configuration management functions**：版本控制、变更管理、审计和报告
