# Chapter 31 Project Management Concepts

## The Four P’s
项目管理最核心的是把人、产品、过程和项目放在一起看。

- People：最重要的因素
- Product：要做出的软件
- Process：完成工作的框架活动和任务
- Project：让产品落地所需的全部工作

## Stakeholders
项目不是只对开发者负责，而是对所有干系人负责。

- senior managers
- project managers
- practitioners
- customers
- end-users

## Team Leader and MOI
项目负责人要同时具备三种能力。

- motivation：激励团队
- organization：组织过程和任务
- ideas / innovation：鼓励创新

## Software Teams and Organizational Paradigms
团队结构要适配问题，而不是套模板。

- closed paradigm
- random paradigm
- open paradigm
- synchronous paradigm
- 选择结构时要考虑规模、复杂度、期限、模块化程度和沟通需求

## Avoid Team Toxicity
团队失控会直接拖垮项目。

- frenzied work atmosphere
- high frustration
- poor coordination
- unclear roles
- repeated failure

## Agile Teams and Coordination
敏捷团队强调信任、自组织和高效沟通。

- self-organizing
- skills should match the problem
- communication can be formal or informal
- electronic and interpersonal communication should be combined as needed

## Product Scope and Problem Decomposition
先定义范围，再拆解问题。

- scope context
- information objectives
- function and performance
- reliability / interface / security
- then decompose into functions, data objects, or problem classes

## The Process
项目过程要先定框架，再定任务集。

- consider project characteristics
- determine rigor
- define task sets
- each task set includes work products, QA points and milestones

## Melding the Problem and the Process
好的项目管理要把“做什么”和“怎么做”结合起来。

- problem context drives process choice
- process should fit the project
- task sets should be mapped to scope

## Common-Sense Approach to Projects
项目管理的常识很朴素，但很重要。

- start on the right foot
- maintain momentum
- track progress
- make smart decisions
- conduct postmortem analysis

## Critical Practices
一些实践会显著提高项目成功率。

- formal risk management
- empirical estimation
- metrics-based management
- earned value tracking
- defect tracking
- people-aware management
