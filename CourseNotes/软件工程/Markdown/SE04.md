# Chapter 4 Process Models

## 4.1 Prescriptive Models
规定性过程模型强调有序、可控的软件工程活动。

- 它们并不反对变化，而是希望变化可管理
- 软件开发要在结构和灵活性之间取得平衡

## Waterfall Model
瀑布模型是最经典的顺序过程模型。

- communication
- planning
- modeling
- construction
- deployment
- 现实中很少严格按顺序一次走完

## Incremental Process Models
增量模型把产品拆成多个可交付版本。

- core product first
- later increments add more features
- RAD 依赖足够的人力和较强的模块化

## Evolutionary Process Models
演化模型更适合需求不清晰或风险较高的场景。

- prototyping：先做原型，再逐步逼近目标系统
- spiral：以风险分析驱动迭代
- concurrent development：多个活动并发推进

## 4.2 Specialized Process Models
一些领域需要更专门的过程模型。

- component-based development
- formal methods
- aspect-oriented software development

## 4.3 The Unified Process
UP 是用例驱动、架构中心、迭代增量的软件过程。

- aligned with UML
- 分阶段推进
- 强调结构和演化并重

## 4.4 Personal and Team Process Models
个人过程和团队过程分别关注个体与协作。

- PSP 强调早期发现错误
- TSP 强调自主管理、测量和过程改进
