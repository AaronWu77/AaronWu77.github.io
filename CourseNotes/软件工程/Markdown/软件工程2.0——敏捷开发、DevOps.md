# 敏捷开发与 DevOps

## 敏捷开发内涵
敏捷不是一种流程名词，而是一种应对变化的开发理念。

- 以用户需求进化为核心
- 采用迭代和增量方式开发
- 每次迭代都交付可运行软件
- 重点是快速响应变化

## 敏捷宣言和原则
敏捷开发强调价值交付和协作。

- 个体和互动高于流程和工具
- 可工作的软件高于详尽的文档
- 客户合作高于合同谈判
- 响应变化高于遵循计划

## 敏捷开发流程
敏捷流程可以拆成需求、设计、编码、测试和部署评估。

- 需求分析：用户故事、优先级、验收标准
- 设计：产品愿景、用户画像、路线图、原型
- 编码：小步快跑、持续集成、单元测试、代码审查
- 测试：自动化测试、缺陷优先级、快速修复
- 部署评估：环境、脚本、监控、持续反馈

## Scrum
Scrum 是轻量级的敏捷管理框架。

- 强调自组织和快速反馈
- 适合复杂项目的迭代增量开发
- 目标是持续提高产品价值

## Scrum 角色
Scrum 团队通常有三种角色。

- Product Owner：维护优先级和价值
- Scrum Master：帮助团队移除障碍
- Team Member：自组织完成工作

## Scrum 会议
Scrum 通过固定会议保持节奏。

- Sprint Planning
- Daily Scrum
- Sprint Review
- Sprint Retrospective

## Scrum 工具
Scrum 常用的可视化工具很简单但有效。

- Product Backlog
- Task Board
- Burndown Chart

## DevOps 概念
DevOps 把开发和运维看成一个连续交付链。

- Dev + Ops
- 通过自动化提高交付频率和可靠性
- 目标是更快地构建、测试、发布和运营

## BizDevOps / DevSecOps
更成熟的组织会把业务和安全一起纳入流程。

- BizDevOps：业务、开发、运维一体化
- DevSecOps：把安全左移到开发流程中
- 共同目标是端到端交付和持续治理
