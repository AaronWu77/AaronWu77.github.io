# Chapter 10 Requirements Modeling: Class-Based Methods

## Requirements Modeling Strategies
需求建模常见两条线：structured analysis 和 object-oriented analysis。

- structured analysis：把数据和处理过程分开看
- object-oriented analysis：聚焦类、对象及其协作
- 两者最终都要服务于客户需求

## Object-Oriented Concepts
OO 建模的核心概念是 class 和 object。

- class / object
- attributes / operations
- encapsulation / instantiation
- inheritance

## Classes
类可以看成一类相似对象的模板。

- class 是对同类事物的抽象描述
- superclass 建立层次结构
- instance 是类的具体对象

## Methods
方法（method）也叫 operation 或 service。

- 方法封装在类内部
- 方法通过 message passing 被调用
- 方法负责操纵类的属性

## Encapsulation and Hiding
封装和信息隐藏是 OO 的核心价值。

- 数据和操作放在一起
- 外部只看到必要接口
- 隐藏内部实现细节

## Class Hierarchy
类层次帮助我们表达泛化与特化关系。

- superclass / subclass
- 继承让共性上移，差异下放
- 便于复用和扩展

## Class-Based Modeling
类建模要同时描述对象、操作、关系和协作。

- objects the system will manipulate
- operations applied to objects
- relationships among objects
- collaborations among classes

## Class-Based Modeling Steps
建模时通常先识别类，再补全属性和操作。

1. 从问题陈述中识别候选类
2. 找出属性
3. 找出操作
4. 反复迭代细化

## Potential Classes
不是所有名词都能变成类，要看它是否真的有建模价值。

- needed services
- multiple or common attributes
- common operations
- essential requirements
- retained information

## CRC Modeling
CRC = Class-Responsibility-Collaborator。

- responsibility：类知道什么、做什么
- collaborator：完成责任时需要协作的类
- 适合早期快速检查类设计

## Class Types
常见分析类分三类。

- entity class：业务实体
- boundary class：界面边界
- controller class：协调一次工作流

## Guidelines for Responsibilities
职责分配要让“信息”和“行为”留在同一类里。

- 一个类负责一类明确的事情
- 相关信息尽量局部化
- 不要把职责拆得太散

## Associations and Dependencies
类与类之间通过关联和依赖建立联系。

- association：对象之间的联系
- multiplicity：数量关系
- dependency：一方变化会影响另一方
