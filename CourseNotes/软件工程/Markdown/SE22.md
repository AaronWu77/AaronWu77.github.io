# Chapter 22 Software Testing Strategies

## Software Testing
测试的目的，是在交付前尽量找到错误。

- testing exercises a program with the intent to find errors
- testing shows errors, requirements conformance, performance, and quality signals

## Strategic Approach
好的测试策略从早期评审开始。

- technical reviews before testing
- start at the component level and move outward
- different techniques fit different stages
- testing and debugging are different activities

## Verification and Validation
V&V 是测试策略的基础。

- verification：we building the product right?
- validation：are we building the right product?

## Who Tests the Software?
测试既是开发者的事，也是独立测试者的事。

- developer knows the system but tends to test gently
- independent tester tries to break the system
- large projects often need both

## Testing Strategy
测试通常按从小到大的顺序推进。

- unit test
- integration test
- validation test
- system test

## Strategic Issues
测试前先把目标和输入条件说清楚。

- quantify requirements early
- state test objectives explicitly
- know the user profiles
- build rapid-cycle testing into the plan
- use reviews as filters

## Unit Testing
单元测试关注一个可测试的最小单元。

- interface
- local data structures
- boundary conditions
- independent paths
- error handling paths

## Integration Testing
集成测试关心模块之间如何一起工作。

- big bang
- top-down
- bottom-up
- sandwich

## Regression and Smoke Testing
回归测试和冒烟测试用于控制变更风险。

- regression testing checks side effects after change
- smoke testing catches show-stopper errors in builds
- both are often automated

## High-Order Testing
系统级和高阶测试看的是更完整的运行场景。

- validation testing
- system testing
- alpha/beta testing
- recovery testing
- security testing
- stress testing
- performance testing

## Debugging Preview
测试之后还要面对调试。

- debugging is a diagnostic process
- symptoms and causes may be separated
- use tools, logic, and regression tests to confirm the fix
